# Speed Math (Brain Teasers)

A lean starting point for a brain-teasers site. First game: **Speed Math** —
pick a start delay, then solve addition/subtraction/multiplication questions
(numbers 2–100) as fast as you can. No Enter key — a correct answer is
detected the instant you finish typing it and the next question appears
immediately. Wrong input just sits there until you fix it.

Questions are generated by the **Google Gemini API** on the backend. If
Gemini is unreachable (no key set, rate-limited, network hiccup) the backend
silently falls back to generating the question locally in Python, so the
game never breaks.

## 1. Backend setup

```bash
cd backend
python -m venv venv
source venv/bin/activate      # Windows: venv\Scripts\activate
pip install -r requirements.txt

cp .env.example .env
# open .env and paste your key from https://aistudio.google.com/apikey
```

Run it:

```bash
python app.py
```

This starts the API at `http://127.0.0.1:5000`. Check it's alive:

```bash
curl http://127.0.0.1:5000/api/health
curl http://127.0.0.1:5000/api/question
```

## 2. Frontend

No build step — it's plain HTML/CSS/JS. Just open `frontend/index.html`
in a browser, or serve it so it doesn't run as a bare `file://` page:

```bash
cd frontend
python -m http.server 8000
# then visit http://127.0.0.1:8000
```

If you serve the frontend from a different host/port later, update
`API_BASE` at the top of `script.js`.

## How the game logic works

- You choose a start delay in seconds → a countdown runs → the first
  question loads from `/api/question`.
- The backend prompts Gemini with a fixed instruction ("inbuilt prompt" in
  `app.py`) to return one question as strict JSON: two integers between
  2–100, an operator (+, -, ×), and the answer. The backend re-checks the
  math itself before trusting it.
- The frontend keeps the answer in memory (not shown) and checks it on
  every keystroke (`input` event) — no Enter/submit button needed.
- Correct → instantly fetches the next question and bumps the score.
- Wrong → nothing advances; the field just shakes once you've typed enough
  digits to be wrong, and you keep trying the same question.
- "Stop" ends the session and shows your score + elapsed time.

## Extending it into a full brain-teasers site

Some natural next steps, kept in mind by the current structure:
- Add more games as new backend routes (`/api/riddle`, `/api/pattern`, etc.)
  and new screens in the frontend — `app.py` and `script.js` are small
  enough to grow without a framework yet.
- Add a difficulty selector by widening/narrowing `MIN_NUM`/`MAX_NUM` or the
  operator list in `app.py`.
- Persist high scores — add a tiny SQLite file and one `/api/score` route
  rather than reaching for a full ORM/database up front.
- If you outgrow a single HTML file, move the frontend to a lightweight
  bundler (Vite) later — not needed yet.
